# 视觉验收检查清单

## 目标

确保 HTML / 设计稿落成 Next.js 页面时，不只是功能可跑，而是视觉上严格对齐设计稿，达到可上线标准。

## 验收原则

1. 先静态还原，再加交互。
2. 先桌面端对齐，再检查移动端。
3. 优先检查首屏和核心转化路径。
4. 不凭感觉说“差不多”，必须逐项核对。
5. 页面跑起来不等于视觉还原完成；必须对照设计 / Stitch 截图验收。

## 截图对照验收

视觉验收必须以原始截图为依据，例如 Stitch 交付包中的 `screen.png`。本地页面应在相同或接近视口下截图，并逐项对照。

- [ ] 已保存原始设计截图 / `screen.png` 作为验收基准。
- [ ] 已截取本地页面桌面端截图。
- [ ] 已截取本地页面移动端截图。
- [ ] 首屏布局与原始截图一致。
- [ ] 标题 / 按钮 / 卡片位置和比例一致。
- [ ] section 间距、卡片间距、文字间距接近原始截图。
- [ ] 颜色和字体与设计稿一致或有明确替代说明。
- [ ] 移动端完成单独对照，不只检查桌面端。
- [ ] 无丢图、错位、溢出。
- [ ] 验收结果记录了截图证据，而不是只写“看起来可以”。

## 全局视觉检查

- [ ] 字体家族与设计稿一致或有明确替代说明。
- [ ] 字号层级清晰：H1/H2/body/small 不混乱。
- [ ] 字重与设计稿接近。
- [ ] 行高可读，无文字拥挤。
- [ ] 主色、辅助色、背景色一致。
- [ ] 按钮圆角、边框、阴影一致。
- [ ] 卡片间距、section 间距一致。
- [ ] 页面最大宽度和容器 padding 一致。
- [ ] 无明显横向溢出。
- [ ] 无 console 残留或明显报错。

## 页面区块检查

### Header / NavBar

- [ ] Logo/wordmark 位置正确。
- [ ] 导航项顺序正确。
- [ ] CTA 按钮样式突出。
- [ ] 移动端菜单按钮可见且可点击。
- [ ] 登录按钮/认证入口不会挤压导航。

### Hero

- [ ] H1 与设计稿一致。
- [ ] 副标题不换行异常。
- [ ] CTA 位置、尺寸、颜色正确。
- [ ] 首屏视觉重心清晰。
- [ ] 首屏不出现明显空白或元素错位。

### 内容 Section

- [ ] 标题层级正确。
- [ ] 卡片数量、顺序与设计稿/PRD 一致。
- [ ] 卡片内部 padding 一致。
- [ ] 图文对齐，无错位。
- [ ] 重复区块使用一致样式。

### FAQ

- [ ] 问题/答案间距清晰。
- [ ] 折叠交互如有，展开/收起状态正常。
- [ ] FAQ 文案不溢出。

### Footer

- [ ] Footer 链接完整：Generator、Pricing、Privacy、Terms、Cookies 等。
- [ ] 法律页链接可点击。
- [ ] Footer 在短页面也不悬空错位。

## SEO / 内容可见性检查

- [ ] H1 每页唯一。
- [ ] 页面核心关键词自然出现，不堆砌。
- [ ] 重要内容不是纯图片。
- [ ] 图片有合理 alt。
- [ ] 法律页内容可读、无空白页。

## 状态检查

### Loading

- [ ] 生成器/支付/认证 loading 状态可见。
- [ ] loading 时按钮不会重复提交。

### Error

- [ ] API 失败时有错误提示。
- [ ] 错误提示不会破坏布局。
- [ ] 用户知道下一步怎么做。

### Empty

- [ ] Dashboard 空状态有说明。
- [ ] 历史记录为空时不显示破损卡片。

## 验收视口

至少检查：

- Desktop: 1440px
- Laptop: 1280px
- Tablet: 768px
- Mobile: 390px
- Small mobile: 360px

## P0 / P1 / P2 分级

- P0：阻塞上线。核心页面错位、主 CTA 不可见、页面白屏、移动端不可用。
- P1：上线前必须修。明显间距/颜色/排版问题、重要文案溢出。
- P2：可后续优化。细节间距、弱视觉 polish、非核心区块轻微差异。
