# 交互补全检查清单

## 目标

页面不是静态海报。HTML / 设计包落成 Next.js 工程后，必须确认用户点击以后会发生什么，把页面从“能看”验收到“能用”。

## 核心原则

1. 所有看起来可点击的元素，都必须有真实行为。
2. 所有核心 CTA 都必须有反馈：跳转、打开弹窗、提交、loading、错误提示或成功提示。
3. 移动端交互必须单独验证，不能只看桌面端。
4. FAQ、菜单、表单这类有状态组件必须验证展开、关闭、提交、异常状态。
5. 法律页、外链、mailto 不是装饰链接，必须能访问或唤起正确客户端。

## 固定检查项

### 1. Header 导航

图片依据：

```txt
Header 导航
点击可跳转
```

检查：

- [ ] Header 中每个导航项都有明确 `href`。
- [ ] 点击后进入正确页面或正确锚点。
- [ ] 当前页 / hover / focus 状态清晰。
- [ ] 不存在 `href="#"`、空链接或 404。

### 2. CTA 按钮

图片依据：

```txt
CTA 按钮
点击有反馈
```

检查：

- [ ] 主要 CTA 点击后有真实反馈。
- [ ] 反馈类型明确：跳转 / 打开表单 / 提交 / loading / success / error。
- [ ] 按钮不可用时有明确 disabled 或提示状态。
- [ ] 不存在只有样式、没有行为的按钮。

### 3. FAQ 展开收起

图片依据：

```txt
FAQ 展开收起
点击展开/收起
```

检查：

- [ ] FAQ 可展开。
- [ ] FAQ 可收起。
- [ ] `aria-expanded` 与展开状态一致。
- [ ] 键盘可聚焦和触发。
- [ ] 移动端点击区域足够大。

### 4. 移动端菜单

图片依据：

```txt
移动端菜单
点击可打开/关闭
```

检查：

- [ ] 移动端菜单按钮可打开菜单。
- [ ] 菜单可关闭。
- [ ] 点击菜单项后按预期跳转或关闭菜单。
- [ ] 菜单不会造成横向滚动或遮挡核心内容。
- [ ] Escape / 点击遮罩关闭如已设计，需验证可用。

### 5. 页面内锚点

图片依据：

```txt
页面内锚点
平滑滚动定位
```

检查：

- [ ] 页面内锚点目标 `id` 存在。
- [ ] 点击后滚动到正确区块。
- [ ] 固定 Header 不遮挡锚点标题。
- [ ] 平滑滚动不影响可访问性。

### 6. 表单入口

图片依据：

```txt
表单入口
点击打开表单
```

检查：

- [ ] 表单入口点击后打开表单或跳转到表单区。
- [ ] 输入框可填写。
- [ ] 必填校验、错误提示、成功提示清晰。
- [ ] 提交中有 loading 状态。
- [ ] 浏览器自动化和真实用户输入路径都能触发表单状态。

### 7. mailto 联系方式

图片依据：

```txt
mailto 联系方式
点击唤起邮件客户端
```

检查：

- [ ] 邮箱链接使用 `mailto:`。
- [ ] 邮箱地址正确。
- [ ] 点击后能唤起邮件客户端或进入系统默认处理。
- [ ] 文案说明清晰，用户知道这是邮件联系。

### 8. 外链打开方式

图片依据：

```txt
外链打开方式
新标签页打开
```

检查：

- [ ] 外链使用新标签页打开。
- [ ] `target="_blank"` 时包含 `rel="noopener noreferrer"`。
- [ ] 外链地址有效。
- [ ] 外链文案让用户知道会离开当前站点。

### 9. 法律页链接

图片依据：

```txt
法律页链接
隐私、条款、免责声明
```

检查：

- [ ] 隐私页可访问。
- [ ] 条款页可访问。
- [ ] 免责声明页如站点需要，必须可访问。
- [ ] Footer / 菜单中的法律页链接不 404。
- [ ] 法律页不要只存在 sitemap 中，页面入口也要可点击。

## 与本项目当前规范的关系

- `docs/routing.md`：负责确认导航、页面和法律页是否有明确路由。
- `docs/component-library.md`：负责确认 Header / Footer / FAQ / 表单等交互组件是否统一拆分。
- `docs/responsive-checklist.md`：负责确认移动端菜单和触控区域可用。
- `docs/code-landing-troubleshooting.md`：负责排查按钮无行为、FAQ 状态未绑定、script 不适配 React 等问题。
- 本文档负责最后一层点击验收：逐项确认用户点击以后发生什么。
