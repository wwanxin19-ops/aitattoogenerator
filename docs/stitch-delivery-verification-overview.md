# Stitch 交付包核验总览

**来源**: 网站前端开发实战课程 — 第三部分
**用途**: 接收 Stitch 设计包后的"能不能施工"判定框架

---

## 核心原则

> **开工前先确认：这个设计包能不能施工**

"可施工"是开工的硬性门槛。任何一项不通过，必须退回设计方补充，不能带着问题开工。

---

## 核验五大维度

| 维度 | 检查内容 | 通过标准 |
|------|----------|----------|
| **文件核对** | 交付包包含所有必需文件 | 无缺失文件 |
| **页面截图核对** | 截图与代码是否对应 | 截图能正常打开，与代码一致 |
| **组件与样式** | 组件拆分是否合理、样式是否规范 | 组件边界清晰，样式无冲突 |
| **设计系统检查** | 设计令牌、变量、规范是否完整 | DESIGN.md 完整可读 |
| **资源完整性** | 图片、字体、图标等资源是否齐全 | public/ 目录资源完整 |

---

## 标准交付物

接收的 Stitch 交付包必须包含以下文件：

```
delivery-package/
├── code.html          # 页面 HTML 源码
├── screen.png         # 页面截图
└── DESIGN.md          # 设计文档/规范说明
```

对应到本项目结构：

```
aitattoogenerator/
├── docs/              # 工程文档（对应 DESIGN.md）
├── src/app/           # 页面源码（对应 code.html）
├── public/            # 静态资源
└── screenshots/       # 页面截图存档（对应 screen.png）
```

---

## 核验清单（6项全过 = 可施工）

- [ ] **文件完整** — 所有必需文件已接收
- [ ] **页面可打开** — 构建成功，页面可访问
- [ ] **资源齐全** — 图片、字体、图标无缺失
- [ ] **样式规范** — 无 ESLint/Prettier 错误
- [ ] **结构清晰** — 目录结构合理，组件边界清晰
- [ ] **通过** — 以上5项全部通过

### 自动化核验命令

```bash
# 1. 文件完整性检查
ls -la docs/ src/app/ public/ && echo "✓ 文件完整"

# 2. 页面可构建检查
npm run build && echo "✓ 页面可打开"

# 3. 资源完整性检查
find public -type f | wc -l && echo "✓ 资源齐全"

# 4. 样式规范检查
npx eslint . && npx prettier --check . && echo "✓ 样式规范"

# 5. 结构清晰检查
tree -L 3 src/ && echo "✓ 结构清晰"
```

---

## "可施工"判定标准

必须同时满足：

1. 所有文档已阅读并确认
2. 构建命令 `npm run build` 成功（退出码 0）
3. 所有页面路由可访问
4. 所有图片资源加载正常
5. 无 ESLint/Prettier 错误
6. Git 工作树干净（无未提交修改）
